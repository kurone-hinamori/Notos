# Notos

ローカルLLM(Ollama)を使って、カクヨムに連載する日本語のライトノベル風の物語を生成する Windows デスクトップアプリです。

- 技術構成: Tauri 2 + React 19 + TypeScript 7
- 実行ファイル: `notos.exe`
- 前提: `http://127.0.0.1:11434` で Ollama が動作していること

## 機能

| 機能 | 内容 |
| --- | --- |
| カクヨム連載 | 連載の名前の下に話(章)が並び、各話を4回分(エピソード、1回2,000〜2,500字)に分けて、回ごとのサブタイトルを自動で付ける。「カクヨム投稿」タブで、キャッチコピー(35字まで)・紹介文・タグ(8個まで、「AI本文利用」は固定)の自動作成と編集、投稿用のコピー・テキスト保存ができる |
| 話ごとのガチャ | キーワードを指定すると、タイトル・あらすじ・登場人物の案を提示。気に入るまで何度でも引き直せる |
| 複製して作り直し | 作成済みの連載の設定を引き継いで、新しく作り直せる。元の連載はそのまま残る |
| 長編・短編集(閲覧のみ) | 以前のバージョンで作った長編・短編集は、一覧から開いて読む・直す・EPUBにすることができる(新しくは作れない) |
| 共通の登場人物 | 話をまたいで登場する人物を、手入力・ガチャ・各話の設定資料からの登録で用意できる。各話で出演者を選ぶと同一人物として扱われ、連作短編では前の話までの経緯も引き継ぐ。他の話の名前は別人に使わない |
| タイトルの指定 | ガチャの前にタイトルを入力すると、そのタイトルに沿った案を考える |
| 使ってほしいセリフ | 指定したセリフを本文で必ずそのまま、上から順番に使う。構成の作成時に使う場面を決め、書いた後に本文に入っているかを確認して、無ければ書き直す。校閲でも書き換えない |
| おまかせ生成 | 各話のタイトル・キーワード・セリフ・出演者だけ決めておけば、前の話が書き上がるたびに次の話のあらすじを自動で作って最後まで生成する |
| 共通の場所・品物・用語 | 全話で同じものとして扱う設定。経緯(壊れた、持ち主が変わった など)も後の話に引き継ぐ |
| 登場する話と入手のタイミング | 共通の場所・品物・用語ごとに「第N話から登場」を指定でき、それより前の話には渡さない。品物は「その話の途中で手に入れる」を指定すると、手に入れる場面を構成の作成時に決め、それより前の場面では使わないよう場面ごとに指示する |
| 本文の自動生成 | 話ごとに 設定資料 → 場面構成 → 場面ごとの執筆。「本文」タブで場面(連載1回分)ごとに読み・直し、場面だけを書き直せる |
| 設定資料 | 登場人物・地名・重要な品物・用語・世界観・年表を話ごとに作成し、書いた本文から新事実を自動反映。各話の設定資料は「連載の情報」タブで、共通の設定と並べて確認・編集できる |
| 校閲・整合性 | 場面ごとに、誤字脱字・文法の校閲、設定資料との矛盾点検(該当箇所を自動修正、修正できないものは指摘として表示) |
| 数字の表記の統一 | 校閲のときに「3000円」と「三千円」のような混在を、漢数字(縦書き向け・初期設定。三〇〇〇円・百万円・十七歳のように書く)または算用数字に機械的に統一する。「一人」「一瞬」「十分な」などの語はそのまま残す |
| 一覧・詳細・編集 | 作成済みの連載を一覧し、概要・本文・設定資料を直接編集可能(自動保存) |
| EPUB 出力 | 縦書き・右開きの EPUB 3(巻末に設定資料を付けることも可能) |
| 表紙・口絵・挿絵 | 別アプリとの連携を予定(現在は準備中) |
| 自動アップデート | 起動時に GitHub Releases を確認し、新版があれば更新を案内 |

物語は `%APPDATA%\io.github.kurone-hinamori.notos\stories\` に JSON で保存されます。

## 使い方

1. [Releases](https://github.com/kurone-hinamori/Notos/releases) からインストーラーを入手してインストール
2. Ollama を起動し、モデルを用意しておく(例: `ollama pull qwen3`)
3. Notos の「設定」で使用するモデルと筆名を選ぶ
4. 「新しい連載」で連載の名前・キーワード・共通の登場人物などを決めて作成する
5. 「話の一覧と制作」で話ごとにガチャを引いて概要を決め、「未完成の話をすべて生成」(または各話の「制作」タブ)で本文を作る。途中で止めても続きから再開できます
6. 「カクヨム投稿」タブで掲載情報を作り、各回のサブタイトルと本文をコピーして投稿する

> 1話(4回分)の生成には、モデルとマシンによっては1時間前後かかります。日本語が得意な 20B 以上のモデルを推奨します。
> 設定の「コンテキスト長」は 16,384 以上を推奨します。

## 開発

```bash
npm install
npm run tauri dev      # 開発起動
npm run tauri build    # インストーラー作成
```

必要なもの: Node.js 22+, Rust (stable), WebView2。

## リリースと自動アップデート

`v*` タグを push すると GitHub Actions(`.github/workflows/release.yml`)が Windows 版をビルドし、
署名付きインストーラーと `latest.json` を Releases に公開します。

```bash
# package.json / src-tauri/tauri.conf.json / src-tauri/Cargo.toml のバージョンを上げてから
git tag v0.1.1
git push origin v0.1.1
```

リポジトリのシークレットに更新署名用の鍵が必要です(`TAURI_SIGNING_PRIVATE_KEY`、パスワードを設定した場合は `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`)。
鍵は `npx tauri signer generate -w ~/.tauri/notos.key` で作成し、公開鍵を `tauri.conf.json` の `plugins.updater.pubkey` に設定します。
**秘密鍵はリポジトリにコミットしないでください。紛失すると既存ユーザーへ更新を配信できなくなります。**
